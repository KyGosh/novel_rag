## 决策记录

- 按阶段 P0→P7 推进，模块分阶段逐步实现，不按模块顺序开发。
- 每个阶段开一个新会话，靠本文件交接；subagent 只用于查资料和代码审查。
- 计划和方案阶段只讲思路，不写详细代码。
- 目标书籍为《冰与火之歌》中文版全五卷，P1–P3 先只用卷一。原文受版权保护，只在本地处理，不入库。
- LLM 选用 Kimi（Moonshot，OpenAI 兼容接口）。（2026-11-06 已改为 DeepSeek，见下文"LLM 切换为 DeepSeek"；下面几条提到 Kimi 的记录保留为历史）
- Embedding（bge-m3）和 Reranker（bge-reranker-v2-m3）在本地 GPU 上运行。
- 版本：ES 8.19.23 + IK 8.19.23、Milvus 2.6.25、Neo4j 5.26.32-community（LTS），Python 3.11。
- 阅读进度和防剧透统一用全局 `reading_order` / `max_reading_order`（按卷序 → 章序编号）。
- 规范化全文 `text.txt` 必须先定稿，再标注评测集（金标按"卷 + 章 + 字符区间"标注）。
- 章节摘要放在 P4，与"情节类"路由一起做。

- 系统是通用的：书籍专属信息（目录、别名表、POV 映射、schema 扩展）都是可选配置，没有配置也能跑通。原文的 sha256 由导入流程自动记录，不需要人工提供版本信息。
- 输入支持 txt / md / epub / pdf（仅限有文字层的 pdf；扫描版暂不支持，OCR 留作以后的插件）。各格式解析后统一成同一种中间表示，下游步骤不感知格式。
- 插图分两步处理：P1 只做提取和过滤（锚定到正文位置）；用视觉模型生成描述并入库是 P5 的可选增强，届时再决定用 Kimi 的视觉模型还是本地模型。
- Kimi 的模型名不写死，在 config 中按任务（抽取、生成、judge）分别配置。
- 硬件：RTX 4060 Ti 8GB（驱动支持 CUDA 13.3）、内存 32GB、Ryzen 7 5700X。
- 部署位置：ES、Milvus、Neo4j 跑在 Docker Desktop 容器里（WSL2 后端，数据用命名卷）；Python 应用和模型在开发期（P0–P5）跑在 Windows 原生环境，通过 localhost 端口访问容器；到 P6 再把应用打包成 Linux 镜像，用 compose 统一编排。代码保持跨平台。WSL 的内存上限设为 12GB，其余内存留给 Windows 端的模型和 IDE。

- A 线设计（2026-10-26）：
  - 切句：句末标点 + 后引号吞入；引号内不断句（超过 200 字的对话允许断开）；省略号只在后引号前或段尾算句末；引语后紧跟归属语（"他说"）时与归属语算同一句，避免切出孤立的短句。
  - 分块：只切章节正文，章节标题作为元数据（是否加入编码文本由 `embed_text_template` 消融决定）；整句贪心到 500 字、上限 800、重叠 ≤ 90 字整句、章末 < 150 字并入前块；不变量（切片一致、不跨章、全覆盖、确定性）在代码中检查。chunk 版本 = 参数 + 切句 / 分块规则版本的 hash。
  - small-to-big（命中块扩展到 `seq ± 1` 或父块）仍按原设计放在 P2，rerank 之后做，用"固定 token 预算下的证据覆盖率"证明收益；P1 baseline 只用单一粒度，避免大块虚高 Recall。
  - token 计数经 `llm/` 的 `TokenCounter`（bge-reranker tokenizer），transformers 仍只在 `llm/` 中 import。
  - 评测：相关性 = 证据区间与 chunk 重叠 ≥ min(区间 50%, 50 字)；Recall@K 按证据统计；默认只跑 dev，test 需显式 `--split test`；baseline 不开防剧透过滤（`--spoiler-filter` 作为单独实验）；结果目录不含原文。

    - **small-to-big ±1 在固定 token 预算下显著有害**：cov@4000 −0.228（邻块挤占预算，挤掉了排名靠后但含证据的块）。固定流程默认不扩展；"按需读上下文"留给 P4 Agent 的工具（读邻近块 / 章节原文），由模型决定何时扩展。

- **P4 决策（2026-11-12）**：
  - 工具层是纯函数，阅读进度和检索范围由运行环境注入，模型不可见；原文检索返回 chunk 全文（原始观察只交给反思环节）。
  - Agent 循环为"规划 → 行动 → 执行 → 反思 → 作答"；行动环节看不到原始观察，证据笔记由单独的反思调用生成，是唯一跨轮保留的证据。
  - 上限默认值：6 轮、12 次工具调用、每题约 4 万 token（冒烟子集上微调，P5 做敏感性消融）。
  - 闭卷 / 固定 RAG / 固定 GraphRAG / Agent 共用同一个作答环节、同一个模型和 4000 token 的证据预算。
  - 答案评分：规则匹配 + DeepSeek judge；judge 一致率用约 50 条答案验证（Claude 预标、用户核对）。
  - 图谱范围（全量 / 只用人物）放到 P5，与"去掉图谱工具"的消融一起决定；P4 只统计图谱工具的使用和贡献。
  - P3.1 遗留的"单段支持的专属称呼不作别名"暂不处理。
  - P4 只跑 v1 dev，test 留到 P5；Agent 至少跑两次，正式延迟在独占 GPU、逐题顺序执行的单独运行中测量。

- **P4 实现（2026-11-12，分支 `p4-agent`）**：
  - `llm/`：对话接口增加 `tools`（function calling，同步 / 异步）与 `sample`（采样编号）；返回 `ToolCall`（原始参数串 + 解析结果；非法 JSON 不在 llm/ 报错，原样上交）。缓存键在带工具 / sample≠0 时才加入工具 schema 与采样编号，**旧缓存键不变**（P3 的抽取 / 摘要缓存不失效）。`ScriptedChatModel` 按 prompt 版本分脚本返回工具调用或回答。新增任务配置 `agent` / `agent_thinking` / `reflect` / `answer` / `answer_judge`（judge 温度 0）。
  - `tools/`：6 个工具——`search_text`（P2 基线链路，可限定卷、章节范围、提到某实体的段落；实体限定用 es2 的 `entity_ids` 取 chunk 白名单，`SearchFilter` 新增 `chunk_ids`）、`read_text`（按 chunk_id 前后各扩展 ≤3 块，不跨章）、`search_summaries`、`read_summary`（事件带证据 chunk_id）、`find_entity`、`graph_query`（profile / between / paths / neighbors / timeline / title_holders / mentions 一个工具多种操作）。`ToolContext`（阅读进度、检索范围）由运行环境注入，不在参数 schema 里（schema 禁止额外字段，模型传 `max_reading_order` 会被拒）。`Toolbox` 统一处理：工具名 / 参数校验 → 结构化错误；超时 / 连接类错误按类名识别、指数退避重试 2 次；其余错误不重试；**防剧透兜底断言**（观察中的每个 chunk、证据、位置都 ≤ 阅读进度且在检索范围内，否则抛 `SpoilerLeak`，该题记为 `spoiler_violation`）；输出硬上限 6000 字。图谱渲染对单证据关系注明“单条证据，建议回原文核实”。题与题并发时，检索链路的 GPU 模型由一把锁串行。
  - `qa/`：统一作答环节（`qa_answer.v1`：简短答案 + 依据 + 引用，`json_object` + 校验；闭卷用同一 prompt 的 `system_closed` 节）；上下文预算 4000 token（reranker tokenizer 计数，与 cov@4000 同口径）；引用校验（固定 RAG 只能引上下文里的 chunk、Agent 只能引笔记里的 chunk）；弃答语“原文未提及”。判分：弃答直接记 abstain；规则匹配（NFKC、去间隔号 / 标点 / 空白后包含，长度 ≥2）；其余交 judge（`answer_judge.v1`，不看证据）。运行器逐题并发、落盘不含原文的 `per_question.jsonl`，含原文的完整 trace 在 `data/traces/`。
  - `agent/`（langgraph 1.2.20，只用 StateGraph + 条件边）：plan → act → execute → reflect →（act | answer）。行动环节只看问题、计划、笔记、证据现状、行动记录（结果概况只有编号、位置、候选实体 ID），**看不到原始观察**；反思环节读本轮原始观察，产出笔记（结论 + chunk_id + ≤40 字引文；chunk 不在本轮观察中则作废；引文是否真在原文里记为 `quote_ok`）和一句证据现状。上限：6 轮、12 次工具调用、每题 4 万 token；**token 上限按上一轮的花费预估**（冒烟迭代 a1 中发现只在轮前检查会超出一整轮，最多到 5.3 万），每轮最多 4 个并行调用，连续 3 轮只有错误 → `error_streak`；不调工具也不调 finish → `finish_implicit`。
  - 冒烟子集：v1 dev 每类 6 题（按 hash 固定，`scripts/run_qa.py --smoke`）。迭代记录：a1（v1 prompts）0.875 / 23.4k token；a2（token 上限改为预估）0.875 / 21.6k token，没有题超过上限；思考模式（`--thinking`）0.875 / 26.3k token、并发下 P50 延迟约 26 s（关闭思考约 6 s）→ **默认关闭思考**，正式消融留到 P5。prompt 都没有改版（全部 v1），冒烟只迭代了 2 轮。
  - 测试：单测 312 个（含工具层假后端、防剧透参数化断言、Agent 循环 14 个脚本化用例）；集成测试 `tests/integration/test_tools_real.py`（4 个阅读进度 × 9 种调用）通过。导入边界：langgraph 只在 `agent/`，`tools/`、`qa/` 不 import `agent/`。
